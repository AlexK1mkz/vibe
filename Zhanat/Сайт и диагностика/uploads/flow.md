# flow.md — Переход из диагностики в подписку

## 1. Принцип

Диагностика создаёт `client_id` в момент старта теста. Этот идентификатор живёт до оплаты и после неё. Всё остальное — производные от него. Никаких повторных вводов данных на стороне приложения: если человек прошёл диагностику, приложение уже знает, кто он.

## 2. Что передаём

Переход по кнопке **Открыть доступ в приложение** — ссылка вида:

```
https://zhanatpower.com/customer/register
  ?cid=<client_id>          # UUID, создан при старте теста
  &src=diag                 # источник: диагностика
  &seg=hot|warm|cold        # сегмент
  &cs=<1-9>&m=<1-9>&py=<1-9>   # три ключевых числа
  &plan=month|half|year     # выбранный тариф, если выбрал
  &utm_source=...&utm_medium=...&utm_campaign=...&utm_content=...
  &sig=<hmac>               # подпись параметров, чтобы нельзя было подделать сегмент
```

Полный результат теста в URL **не передаётся** — он хранится на сервере диагностики и отдаётся приложению по `cid` через внутренний API. В URL — только то, что нужно для мгновенной персонализации экрана и атрибуции.

Персональные данные (имя, дата, телефон, почта) в URL не попадают.

## 3. Что видит клиент в приложении

### 3.1 Экран входа с `src=diag`

- Заголовок: **Ваш код: CS · M · PY** (три числа крупно, как в отчёте — узнавание)
- Строка: «Диагностика пройдена. Полная картина — внутри»
- Регистрация через Telegram (по умолчанию) с предзаполненной почтой из диагностики
- Выбранный тариф уже подсвечен, если `plan` передан
- Оферта и правила возврата — ссылками у кнопки, галочка согласия не предзаполнена
- Галочка автопродления — отдельная, не предзаполнена

### 3.2 После оплаты

- Первый экран приложения — не общая лента, а карточка «Ваш разбор» с полным отчётом диагностики и кнопкой «Смотреть первый урок»
- Онбординг-видео до 2 минут
- Уведомление в Telegram: «Доступ открыт, ваш разбор сохранён в профиле»

### 3.3 Если ушёл без оплаты

- Через 1 час: письмо «Ваш отчёт» с кнопкой в приложение (та же ссылка с `cid`)
- Через 24 часа: письмо с одним уроком бесплатно и кнопкой
- Через 72 часа: письмо от учителя (кружок или текст), последнее в цепочке
- Сегмент `hot` дополнительно получает звонок из отдела продаж в первые 15 минут

## 4. Как связываем покупку с результатом

### 4.1 На стороне приложения

При регистрации с `cid` приложение:
1. Проверяет подпись `sig`
2. Создаёт пользователя, записывает `cid`, `src`, `seg`, `utm` в профиль
3. Запрашивает у сервера диагностики полный результат по `cid` и сохраняет его в профиль пользователя

### 4.2 Webhook об оплате

Приложение отправляет на сервер диагностики:

```json
{
  "event": "subscription.paid",
  "cid": "<client_id>",
  "user_id": "<id в приложении>",
  "plan": "month|half|year",
  "amount": 24,
  "currency": "USD",
  "paid_at": "2026-09-21T14:03:00Z",
  "provider": "stripe|robokassa"
}
```

Сервер диагностики: меняет статус лида на `subscriber` в Sheets и CRM, пишет событие в аналитику, останавливает цепочку писем.

Те же события для `subscription.cancelled` и `subscription.renewed`.

### 4.3 Если `cid` потерян

Человек прошёл диагностику, но пришёл в приложение с другого устройства или по прямой ссылке. Связка — по почте или Telegram-аккаунту: при регистрации приложение проверяет, есть ли лид с такой почтой, и подтягивает результат. Совпадение по почте — достаточное основание; телефон не используем для связки, только почта и Telegram ID.

## 5. Атрибуция

- `utm` фиксируется при первом заходе на страницу диагностики и хранится в сессии и в записи лида
- Кодовое слово из Instagram-бота передаётся как `utm_content=<слово>` — так видно, какой рилс привёл
- Отдельные метки: `utm_source=instagram&utm_medium=bot` для бота, `utm_source=instagram&utm_medium=bio` для шапки, `utm_source=email&utm_medium=reactivation` для рассылки по базе, `utm_source=site&utm_medium=cta` для кнопки на главной
- В отчёте по продажам школы каждая заявка имеет `cid` — по нему видно, откуда пришёл человек

## 6. Заявка на школу

Кнопка **Разобрать результат на школе** открывает форму на той же странице с предзаполненными именем, телефоном, почтой и датой. Пользователь выбирает мероприятие из списка и отправляет. Запись типа `application` уходит в Telegram немедленно с полным результатом. Отдел продаж звонит с готовой карточкой — ему не нужно ничего спрашивать заново.

## 7. Что нужно от разработчика приложения (Ахмед)

1. Принимать параметры из раздела 2 на `/customer/register`, проверять `sig`
2. Экран входа с персонализацией из 3.1
3. Внутренний API: `GET /api/diag/result?cid=` (с сервера диагностики) — отдать результат в профиль
4. Webhook из 4.2 на URL сервера диагностики при оплате, отмене, продлении
5. Связка по почте/Telegram ID из 4.3
6. Первый экран после оплаты — карточка «Ваш разбор»

## 8. Что нужно от разработчика диагностики

1. Генерация `cid` и `sig`
2. Хранение результата и отдача по API
3. Приём webhook и обновление статусов в Sheets и CRM
4. Цепочка писем с остановкой по событию оплаты

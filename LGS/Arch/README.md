# Сайты LGS: клиентский и для специалистов

Один код, два сайта Института современного NLP / LGS (ТОО «LOGOS»). Сделано по ТЗ версии 2 от 23 ноября 2026: `docs/TZ-LGS-v2.md`.

| Сайт | Для кого | Проект Vercel | Адрес |
|---|---|---|---|
| Клиентский | Холодная аудитория: лендинг, тест «Стеклянный потолок», результат, консультация, интенсив | `lgs-archetype` | https://lgs-archetype.vercel.app |
| Для специалистов | НЛП-практики, мастера, тренеры: лендинг с анкетой | `lgs-specialists` | https://lgs-specialists.vercel.app |

Оба проекта собираются из этого репозитория, Root Directory `LGS/Arch`. База, админка и компоненты общие.

Что ждёт заказчика, собрано в [CONTENT_TODO.md](CONTENT_TODO.md).

## Как сайты разделены

Переменная окружения `SITE` решает, какой сайт открыт на домене.

| `SITE` | Главная `/` | Что недоступно |
|---|---|---|
| `client` | Клиентский лендинг | `/specialists` уводит на `SPECIALISTS_URL` |
| `specialists` | Лендинг специалистов | `/test`, `/result`, `/consultation`, `/intensive` уводят на `CLIENT_URL` |
| не задана | Клиентский лендинг | Ничего: все разделы доступны (разработка и тесты) |

Если адрес второго сайта не задан, вместо редиректа отдаётся 404. Логика лежит в `proxy.ts` и `lib/site.ts`. `/admin`, `/privacy`, `/offer`, `/thanks` есть на обоих доменах.

Счётчики у сайтов свои: `META_PIXEL_ID`, `GA4_ID`, `YM_ID` задаются отдельно в каждом проекте Vercel. Событие `Lead` уходит с параметром `audience=client` или `audience=specialist`.

## Запуск

```bash
npm install
```

```bash
npm run dev
```

Сайт откроется на http://localhost:3000, лендинг специалистов на `/specialists`. Без `DATABASE_URL` используется встроенный Postgres (PGlite), данные лежат в `.data/pglite`. Для админки задайте `ADMIN_PASSWORD` в `.env.local` (образец в `.env.example`).

| Команда | Что делает |
|---|---|
| `npm test` | Модульные тесты: подсчёт, сегментация, контент, запреты, таблица, расписание, телефон |
| `npm run check:texts` | Проверка текстов по запретам раздела 3 ТЗ |
| `npm run test:e2e` | Сквозные тесты в Playwright. Перед первым запуском: `npx playwright install chromium` |
| `npm run typecheck` | Проверка типов |
| `npm run build` | Сборка |

## Тест «Стеклянный потолок»

17 вопросов: сфера, 12 ситуаций (по 4 на деньги, отношения и рост), цена и цель, род занятий и доход. В каждой ситуации четыре варианта: безнадёжность (H), беспомощность (B), недостойность (W) и ресурсный ответ (R).

- Главное убеждение: тип с максимумом баллов. При равенстве побеждает тип, чаще выбранный в сфере из первого вопроса, затем порядок B, W, H.
- Главная сфера: сфера с максимумом ограничивающих ответов, при равенстве сфера из первого вопроса.
- 10 и больше ресурсных ответов дают результат «Свободный ход».
- Сегмент `pro`: работает с людьми или уже учился НЛП. Сегмент `A`: доход от 500 000 ₸. Остальные: `B`. Отметка `priority` (личный звонок): доход от 1 000 000 ₸.

Тест перебирает все 16 777 216 наборов ответов и сверяет результат с независимой реализацией правил.

## Запреты для текстов

`scripts/check-banned.mjs` ищет в JSON, словаре и страницах слова из раздела 3 ТЗ: здоровье и лечение, управление другими, гарантии дохода, исключительные права, ложная срочность, «диагностика», «архетип». Разрешённые формулировки («не диагностика», «распознавать манипуляцию», «со здоровьем мы не работаем») перечислены в `ALLOWED` точными фразами. Тот же список проверяется в `npm test`.

## Заявки

1. Лид создаётся при показе короткого результата, контакт дописывается формой.
2. После контакта лид уходит в GetCourse, в CRM-вебхук и строкой в Google Таблицу (лист «Клиенты»). Анкета специалиста пишется на лист «Специалисты». Как подключить таблицу: [docs/GOOGLE-SHEETS.md](docs/GOOGLE-SHEETS.md).
3. Ошибка записи в таблицу не ломает заявку: строка остаётся в базе с пустым `sheets_synced_at`, крон повторяет запись.
4. В админке две вкладки: клиенты и специалисты. У лида кнопки «Результат», «Консультация», «Интенсив», «Напоминание»: они открывают `wa.me` с готовым текстом, менеджер отправляет сам.
5. Пока ссылки GetCourse не заданы, кнопки оплаты открывают WhatsApp института с текстом «Мой результат теста: … Запишите меня на …».

Вход из Instagram: кодовые слова в ManyChat ведут на `/test?utm_source=instagram&utm_medium=manychat&utm_campaign=СЛОВО`. UTM сохраняются при первом заходе и попадают в базу, админку и таблицу.

## База и миграция

Таблицы создаются и обновляются при первом обращении (`lib/db/schema.ts` → `DDL`). Миграция с версии 1 совместима назад: новые поля добавляются, старые поля архетипов становятся необязательными и не удаляются. После слияния в `main` их можно удалить командой из комментария в `schema.ts`.

Превью-деплои Vercel используют ту же базу, что и боевой сайт: тестовые заявки с превью нужно удалять в админке.

## Деплой

- Каждый коммит в `main`, который меняет папку `LGS/Arch`, выкладывает оба проекта. Коммиты в других папках репозитория Vercel показывает как Canceled: это правило пропуска сборки, а не ошибка.
- Ветки получают превью-адреса вида `lgs-archetype-git-ВЕТКА-alex-kim1.vercel.app`. Превью закрыты входом в Vercel.
- Крон цепочки сообщений и повторов записи в таблицу запускается раз в сутки и только в проекте `lgs-archetype`, где задан `CRON_SECRET`.

## Ограничения

- Ограничение частоты по IP хранится в памяти процесса: это защита от простых ботов, а не точный лимит.
- Событие `Purchase` уходит в счётчики со страницы `/thanks` после подтверждения оплаты вебхуком.
- События в отладчиках Pixel, GA4 и Метрики не проверялись: идентификаторы счётчиков не заданы.
- При смене статуса лида в таблицу дописывается новая строка, а не обновляется прежняя.
- LCP и вес первого экрана не измерялись.

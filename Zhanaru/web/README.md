# Сайт клиники ZhanaRu (Жаңару), Астана

Одностраничный сайт-воронка с первичным тестом и моделью тела. Сделан по `../TZ-zhanaru-site.md`.
Стек: Astro 5 (статическая сборка), островки на React-API с рантаймом Preact (`preact/compat`), TypeScript, Tailwind CSS 4, zustand.

Старый сайт лежит в `../site/` и не тронут: оттуда взяты фото и факты о клинике.

## Как запустить и собрать

```bash
npm install
npm run dev       # разработка, http://localhost:4321
npm run build     # сборка в dist/
npm run preview   # посмотреть собранный сайт
npm test          # unit-тесты подсчёта (Vitest)
npm run e2e       # сквозной сценарий (Playwright; один раз: npx playwright install chromium)
```

Нужен Node.js 20+. Адрес сайта для canonical, sitemap и Open Graph задаётся в `astro.config.mjs`
или переменной `SITE_URL` при сборке: `SITE_URL=https://домен npm run build`.

## Как залить на хостинг

Сайт статический, Node.js на хостинге не нужен.

1. `npm run build`.
2. Залить **содержимое** папки `dist/` в веб-корень (обычно `public_html`) по FTP или через файловый менеджер панели. Скрытый файл `.htaccess` тоже нужен.
3. Включить HTTPS (Let's Encrypt в панели хостинга). Редиректы http → https и www → без www уже в `.htaccess`.
4. Настроить приём заявок:
   - создать бота у @BotFather, добавить его в чат клиники, узнать `chat_id`;
   - скопировать `api/private/config.example.php` в `zhanaru-config.php` **на уровень выше веб-корня** (или в `api/private/config.php`) и заполнить;
   - в `allowed_origins` указать адрес сайта.
5. Подключить Google-таблицу заявок — инструкция в `google-sheets/README.md` (Apps Script + две строки в конфиге).
6. Проверить на боевом домене: отправить форму из блока «Запись» и «Перезвоните мне» из результата теста — заявка должна прийти в Telegram с сегментом и UTM.

Если PHP на хостинге нет: в `src/content/site.ts` поставить `leadEndpoint: ''` — формы исчезнут из сценария, останутся ссылки в WhatsApp.

## Сценарий теста и заявки

Сначала шаг «Давайте познакомимся»: имя, фамилия, телефон и согласие. Заявка уходит клинике сразу
(этап «Контакты, тест не прошёл»), чтобы не терять тех, кто бросит тест на середине. Затем 10 вопросов
(третий — рост и вес ползунками). На последнем ответе открывается WhatsApp с готовым сообщением (имя, индекс, цель,
зоны, чекап), ответы дописываются в ту же заявку по её номеру (этап «Тест пройден»), а на странице показывается результат:
индекс и рекомендованный чекап прямо на карте тела, у каждой зоны внимания — какие анализы посмотреть
(`src/content/recommendations.ts`). Заявки идут через `lead.php` в Telegram, на почту и в Google-таблицу.

- Шкала веса строится от роста (от ИМТ 15 до ИМТ 50), цветные зоны ИМТ и «норма для вашего роста» пересчитываются на лету.
  Пока посетитель не трогал вес, он следует за ростом. Фигура на модели становится шире или уже по ИМТ.
- Отправка заявки — `src/lib/lead.ts`; поля таблицы — `google-sheets/Code.gs`.

## Где менять веса теста

Всё в `src/lib/scoring.ts`:

- `START` — стартовое значение шкал (85), `FLOOR` — нижняя граница (15);
- `BMI_WEIGHTS` — сколько баллов отнимает ИМТ вне нормы (границы ВОЗ 18,5 / 25 / 30 / 35);
- `WEIGHTS` — сколько баллов отнимает каждый ответ у каждой шкалы;
- `goalFor` — формула «цели программы»: `min(90, текущее + (90 − текущее) × 0.8)`, шкалы от 80 — «поддерживаем»;
- `pickDirection` — как из ответов получается направление и чекап;
- `pickSegment` — сегмент A/B/C/D (из вопросов 3, 8, 9; посетителю не показывается);
- `zoneValues` — какие зоны модели подсвечиваются.

После правок запустите `npm test`: тесты в `src/lib/scoring.test.ts` проверяют граничные ответы, направления и сегментацию.

## Модель тела и фото

Модель — детальная фигура, женская или мужская (`public/img/body-f.webp`, `body-m.webp`). Зоны окрашиваются поверх картинки
в режиме смешивания «цвет»: анатомия остаётся видна, оттенок меняется от янтарного к зелёному.

- Разметка зон (где на фигуре голова, щитовидная железа, грудь, печень, живот, таз) — `src/components/body3d/figure.ts`, в долях от размеров картинки.
- Исходник фигур — `scripts/src/body-source.jpg`. Вырезать заново: `node scripts/make-figures.mjs`.
- Фото клиники для слайдера и галереи лежат в `public/img/*.jpg`. После замены фото: `node scripts/make-photos.mjs` — скрипт сделает WebP 480/800/1600 px и кадры 4:3 для слайдера на телефоне.
- Фигуры есть в двух размерах (`body-f.webp` и `body-f-700.webp`); браузер берёт нужный по ширине колонки. Список слайдов первого экрана — `src/content/sections.ts` → `hero.slides`.
- Прежний 3D-манекен (`BodyCanvas.tsx`, `BodySvg.tsx`) оставлен в проекте, но на страницу не подключён и в сборку не попадает. Он пригодится, если появится лицензионная GLB-модель.

## Скорость и SEO

Lighthouse на сборке (`npm run build && npm run preview`), 15.11.2026: телефон — 95 / 100 / 100 / 100
(Performance / Accessibility / Best Practices / SEO), LCP 2,7 с; десктоп — 100 / 100 / 100 / 100.

Что для этого сделано: рантайм Preact вместо React (JS ~100 КБ вместо ~280 КБ), CSS встроен в HTML,
предзагрузка первого фото слайдера и кириллических шрифтов, кадры 4:3 для телефона, остальные слайды грузятся после
загрузки страницы, адаптивные `srcset` у всех фото и фигур, манифест и иконки, кеширование и сжатие в `.htaccess`.
На боевом хостинге итог зависит ещё от скорости сервера и включённого gzip/brotli.

## Аналитика

ID счётчиков — в `src/content/site.ts` → `analytics`. Пока поле пустое, счётчик не загружается.
Счётчики подключаются только после согласия в баннере cookies. События: `quiz_start`, `quiz_step_N`, `quiz_complete`,
`quiz_contact_step`, `result_toggle`, `lead_whatsapp`, `lead_callback`, `cta_click` (для Pixel лиды уходят как `Lead`). Все события дублируются в `window.dataLayer`.

## Казахская версия

Маршрут `/kk/`, переключатель языка и `hreflang` готовы. Пока в `src/i18n/kk.ts` стоит `translated: false`,
страница показывает русские тексты и закрыта от индексации. Чтобы включить: перевести строки в `kk.ts` и контент, поставить `translated: true`.

## Отступления от ТЗ

- **Контакты в начале теста** (решение заказчика от 15.11.2026). По ТЗ результат показывался без контактов; теперь тест начинается с имени, фамилии и телефона, заявка уходит сразу, а в конце — результат и переход в WhatsApp.
- **Вместо 3D-модели — детальная 2D-фигура** (решение заказчика от 14.11.2026). Она слегка поворачивается в перспективе, но не вращается на 360°; WebGL не нужен, поэтому отдельный фолбэк тоже не нужен. `three` и `@react-three/fiber` остались в зависимостях ради отложенного 3D-манекена, в сборку сайта они не попадают.
- **Preact вместо React в браузере** — ради скорости. Код островков остался на React-API; при подключении 3D-манекена на `@react-three/fiber` нужно вернуть `@astrojs/react`.
- **`@react-three/drei` и `motion` не подключены.** Подписи зон — обычный HTML-слой, смена вопросов — CSS-анимация.
- **H1 изменён** с «Чекап и анализы в Астане. Узнайте, где вы теряете энергию» на хук под задачи сегментов A и B: «Энергия — ваш новый статус. Чекап в Астане покажет, где вы её теряете». Ключ «чекап в Астане» в H1 сохранён, «анализы в Астане» остались в title, description и заголовке блока чекапов.
- **Палитра расширена**: к цветам из ТЗ добавлены бирюза, тёплый жёлтый и мягкие цветные подложки (`src/styles/global.css`).
- **Пакетов чекапа не 3–4, а один** — базовый, с реальным составом. Вместо остальных показаны «фокусы»: какие показатели базового чекапа отвечают за задачу. Состав расширенных пакетов клиника ещё не прислала.
